## Архитектурные решения (AD)

- **AD-1** Три уровня спеки: Brain (сменный) / Дирижёр (без LLM) / Исполнители. Ядро никогда не зовёт LLM для своей логики.
- **AD-2** Brain через env `DIRIGENT_BRAIN=kimi|codex|opencode`, сейчас `kimi -p`. Выбор постоянного — по бенчу.
- **AD-3** SQLite WAL, одна БД `/matrix/dirigent/dirigent.db`. Очередь: lease 10 мин + heartbeat 30с, `running` без heartbeat → `ready` (retry с учётом политики шага).
- **AD-4** Квота Codex: tier-1 парсинг stderr/кода выхода (всегда); tier-2 unofficial-probe (флаг `CODEX_QUOTA_PROBE=1`), помечен в коде, отключаем одной настройкой. Никакого обхода ограничений — только чтение.
- **AD-5** Контракт шага machine-checkable: для кода = diff применяется + `go test` зелёные + линт. Сообщение LLM «готово» не является доказательством (спека §5).
- **AD-6** Telegram: демон слушает 127.0.0.1:9310; bot.py получает тонкий маршрут (паттерн alert_intake). Без второго бота.
- **AD-7** Апрувы неблокирующие: шаг → `waiting_approval`, вопрос в телегу с таймаутом и безопасным дефолтом (молчание ≠ согласие). Остальные ветки DAG живут.
- **AD-8** Replan: max 3 пересмотра плана на заказ → эскалация; бюджетные изменения плана — только через апрув.
- **AD-9** Видимость: на старте verbose-уведомления (агрегированные по ветке), `/order <id> --log` даёт хвост. TUI (textual, k9s-стиль: дерево шагов, r/a/k/l/s, шапка с $/токенами/квотой) — фаза 3.5, после Telegram. Веб-панель запрещена до реальной потребности.
- **AD-10** Конкурентность: 2 исполнителя максимум (спека §12), semaphore в планировщике + `CPUQuota=200%` в unit.
- **AD-11** Worktree-изоляция кодинга: `git worktree add .dirigent/<order>-<step>` внутри репо задачи; merge только после апрува проверок; force push и destructive-команды запрещены (спека §8.4).
- **AD-12** Синхронизация пакетов работ — через `/matrix/dirigent/TASKS.md` (этот файл читают я, DeepSeek, позже Codex).

## Принципиальная схема потока

```
заказ (TG/CLI/YAML)
  → Brain: план (шаги DAG, контракты, ресурсы, бюджет)
  → валидация схемы + проверка циклов (код, не LLM)
  → Scheduler: очередь SQLite, lease/heartbeat, semaphore=2
  → Executor adapters: codex | opencode | shell | ...
  → Acceptance checkers (machine-checkable)
  → апрув человеку (неблокирующе) → merge/артефакт
  → отчёт в TG + запись в память
```
