# Telegram-интеграция — спецификация P2 (Draft 1.0, автор: ChatGPT-руководитель)

Принята 18.11.2026. Ключевые решения:
- Существующий bot.py, второго бота нет; TG-адаптер — тонкий прокси к API, без бизнес-логики.
- Уведомления: обязательные (апрувы, done, final fail, бюджет, исчерпание попыток, критический
  ресурс, физическое действие, потеря ресурса) + опциональные. Режимы quiet/normal/verbose
  (по умолчанию verbose на период теста).
- Согласование: карточка (заказ/шаг/причина/последствия/бюджет/TTL) + кнопки
  Разрешить/Отклонить/Подробнее; молчание != согласие; TTL-политика явная; аудит; один раз.
- Команды целевые /dstatus /dorders /dorder /dlog /dagents /dbudget /dpause /dresume
  /dcancel /dapprovals — сверить с уже живыми /orders /order /approve /reject /dpause
  /dresume /dcancel /dbudget (bot_dirigent.py), дубли не вводить.
- Надёжность: transactional outbox в SQLite (событие+запись → sender → подтверждение,
  backoff на ошибках, dedup-key, редактирование карточки где возможно). Заказы не блокируются
  недоступностью TG.

## Поправка P4 «тихий прод» (18.11.2026, после инцидента флуда)

Инцидент 17.11: владелец получил десятки сообщений за минуту от тестовых заказов
('test','t','kill-guard'), pause+resume, дубли done/error, пачку approvals
'Принять результат? ([])' TTL 1 мин; inline-кнопки не работали. Решения:

1. **quiet — дефолт** (`notify.MODE="quiet"`). Владельцу: реальные апрувы,
   `order.error`/`step.retry_refused` (исполнители попыток исчерпаны) и `order.done`
   важных реальных заказов. `order.paused`/`order.resumed` и прочие переходы —
   только UI/аудит (`events`), без TG.
2. **Тестовое/служебное определяется по явным метаданным**, не по вхождению 'test'
   в цель: `repo` под `/matrix/bench-pilot` → test; тип шага `mock.*`/`bench.*`/
   `selfcheck.*` → test; точное имя цели `kill-guard`/`self-check`/`healthcheck` или
   `constraints.test`/`self_check` → service; исключённый repo → service.
   Заказ, которого нет в журнале, — fail-closed. Для таких заказов TG-сообщений нет.
3. **Дедуп и лимиты**: `UNIQUE(dedup_key)` + явная проверка `event_id`; coalescing
   одинаковых order+transition в окне 10 мин; rate-limit 5/мин для НЕ-критических
   (откладываются через `next_retry`, не теряются); апрувы/ошибки идут первыми и
   rate-limit'ом не отбрасываются.
4. **Апрувы**: карточка с кнопками только если есть что решать (артефакты/действия);
   пустой «([ ])» — только аудит (`approval.not_notified`). TTL апрува — из spec, но не
   меньше 5 мин; иначе часовой дефолт. Протухший/решённый апрув перед отправкой
   закрывается (`skipped`), после рестарта — `recover_after_restart()`.
5. **Кнопки**: `callback_data = dgt:apr:<approval_id>:ok|no` (< 64 байт),
   обработчик подтверждает callback ВСЕГДА, проверяет права по Telegram user ID,
   однократность — через API (`/approvals/{aid}/approve|reject`), при просрочке/повторе
   владелец получает понятный alert («Срок решения истёк», «Уже разрешён»).
   Общий `callback_handler` бота больше не перехватывает `dgt:*`.
